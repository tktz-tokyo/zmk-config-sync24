# Phase 1 実施記録: zmk-naginata Commandキー不具合の再現条件固定

本書は `docs_naginata_plan.md` の **フェーズ1（再現条件固定）** を実際に進めるための実務ドキュメントです。  
対象は **macOS / iOS**、かな英数切り替えは既存実装の **HJ=かな(LANG1), FG=英数(LANG2)** を前提とします。

## 1. テスト前提

- キーボード: SYNC24（left/right）
- ファームウェア: 現行 `feat/n-phase4` ベース
- 接続方式:
  - macOS: USB / BT
  - iOS: BT（ハードウェアキーボード）
- 日本語切替:
  - HJ同時押し => かな（LANG1）
  - FG同時押し => 英数（LANG2）

## 2. 失敗再現シナリオ定義（Failing Scenarios）

以下は最低限固定するシナリオです。各シナリオは **10回連続**で実施し、再現回数を記録します。

### S1: macOS / 英数モードで Command ショートカット後に入力が崩れるか

1. FG同時押しで英数へ切り替える
2. 英字を数文字入力（例: `abc`）
3. `Cmd+C`, `Cmd+V`, `Cmd+Tab` を順に実行
4. 再び英字入力
5. 期待: 連続して正常入力できる（取りこぼし・誤変換なし）

### S2: macOS / かなモードで Command ショートカット後に入力が崩れるか

1. HJ同時押しでかなへ切り替える
2. かな入力を数文字実施
3. `Cmd+C`, `Cmd+V`, `Cmd+Tab` を順に実行
4. かな入力に戻る
5. 期待: かな入力状態が破綻しない（意図しない英数化・バッファ残りなし）

### S3: iOS / かな英数トグル直後に Command 系を使った場合

1. HJでかな、FGで英数を3往復
2. 各切替直後に `Cmd+Space` またはアプリ側ショートカットを実行
3. 直後の文字入力を確認
4. 期待: 切替状態と実際入力モードが一致し、次打鍵が崩れない

### S4: 左右 Command 差分確認（macOS優先）

1. 左Commandを使った場合の S1/S2 を実施
2. 右Command（割当がある場合）でも同様実施
3. 期待: 左右で差分が出ない
